# 模型接入与训练说明

## 现状（2026-10-20 更新）

- 项目目录中**没有**陈皮柑专用数据集、标注文件或权重（现有公开数据只有 COCO 的橙类）。
- 毕业设计任务书（本地文件 `实训内容.docx`，未入库）没有可复用的代码、数据或模型。
- 系统目前可以用通用橙类模型做果实检测；成熟度是**框内颜色估算**（青/转色/成熟），不是模型分类；大小分级是相对像素比例。接入陈皮柑专用权重后检测会更准，颜色估算逻辑不变。
- 当前线上模型：`models/orange_orchard_best.pt`，用公开数据集 **Oranges in the field（UNIPA，5025 张果园实拍，CC BY-NC 3.0）** 微调，验证集 **P=0.807 / R=0.736 / mAP50=0.801 / mAP50-95=0.449**（400 张、2842 个框，按果树分组划分）。它能检测树上的橙黄色柑橘；成熟度另做颜色估算。训练品种是国外橙类，**不是陈皮柑专用模型**。详见第 7 节。
- 更早还用 COCO orange 训练过一版（mAP50=0.321，果园照片基本检不出），已被上一版取代，保留作对比，见第 6 节。

## 1. 准备数据

1. 采集果园图片（手机或无人机航拍），尽量覆盖不同光照、距离、遮挡情况和成熟阶段。
2. 用 LabelImg / Labelme / X-AnyLabeling / Roboflow 等工具标注，导出 YOLO 格式。
3. 按以下目录放置（建议 训练:验证 = 8:2）：

```
datasets/chenpigan/
  data.yaml
  images/train/*.jpg   labels/train/*.txt
  images/val/*.jpg     labels/val/*.txt
```

4. 根据实际标注类别修改 `datasets/chenpigan/data.yaml` 的 `names`。模板中的“青果/转色果/成熟果”只是示例；**系统中显示的类别完全来自模型本身**，成熟度等级必须与训练类别一致。

## 2. 训练与验证

```bash
python scripts/train_yolo.py --data datasets/chenpigan/data.yaml --model yolov8n.pt --epochs 100 --imgsz 640 --batch 16
```

- 输出目录：`runs/chenpigan*/`，脚本最后打印验证集的真实 Precision、Recall、mAP50、mAP50-95，请把这些数值写入论文。
- 只验证已有权重：`python scripts/train_yolo.py --val-only --weights models/chenpigan_best.pt`
- 该脚本已经用临时合成数据跑通 1 个 epoch，只说明流程可执行，那组指标没有意义。

## 3. 接入系统

把确认效果的 `best.pt` **手动复制**为 `models/chenpigan_best.pt`（或在 `.env` 中设置 `MODEL_PATH`）。系统会：

- 第一次识别时加载模型，然后进程内缓存，不会每次请求都加载；权重文件修改后会自动重新加载；
- 使用 `MODEL_CONF`、`MODEL_IOU`、`MODEL_DEVICE` 配置；
- 保存每个检测框的坐标、类别、置信度、相对大小，以及结果图和识别耗时；
- 页面上标注识别方式为“YOLO 模型”，不再显示“演示”。

## 4. 大小分级说明

检测框面积占整幅图像的比例小于 0.2% 为“小”，大于 0.8% 为“大”，介于两者之间为“中”（`SIZE_GRADE_THRESHOLDS`）。这是**相对图像的大小**，会受拍摄距离影响，**不代表真实果径**。如需真实果径，需要标定物或深度/测距信息，目前没有实现。

## 5. 演示模式（OpenCV）

没有模型时，用 HSV 橙黄色阈值 + 形态学 + 轮廓圆度筛选来查找橙色近圆区域。它不是深度学习模型，无法识别青果，也容易把其他橙色物体误判成果实，只用来演示业务流程。数据库字段 `recognition_runs.mode = 'opencv_demo'`，页面、估产和报表都会标注为演示。

## 6. 2026-10-20 的训练实验（实际执行，结论：暂不启用）

为了让系统不只停留在演示模式，实际做过一次完整的“采集 → 标注 → 训练 → 验证”实验，过程和结论如下，论文里可以直接引用。

### 6.1 尝试一：爬取网络图片 + 自动标注

- 用 `scripts/build_citrus_dataset.py` 从必应图片搜索抓取关键词（陈皮柑、新会柑、茶枝柑、柑橘果树、砂糖橘等）共 1172 个候选地址，成功下载 **471 张**图片。
- 用 COCO 预训练的 `yolov8n.pt` 里的 orange 类别（class 49）做自动标注，置信度 0.35。
- 结果：**471 张里只有 4 张能检出 orange**。教师模型对果园远景、青果、小目标几乎不响应，自动标注不可用。
- 结论：网络图片只有图像、没有标注框；用现有通用模型自动标注会漏掉绝大部分果实，强行拿这些标签训练等于在错误标签上学习。

### 6.2 尝试二：改用有人工标注的 COCO 数据

- 从 COCO 2017 验证集标注中筛出 orange 类别（category 55）：**76 张图片、236 个真实人工标注框**。
- 脚本 `scripts/build_coco_orange_dataset.py` 下载图片并转换为 YOLO 格式，按 8:2 划分为训练 61 张、验证 15 张。
- 用 `yolov8n.pt` 微调，640×640，batch 8，60 epochs，RTX 4060 上训练约 0.8 分钟。
- 权重保存为 `models/orange_coco_best.pt`，指标文件 `runs/orange_coco/metrics.json`。

验证集指标（15 张图、50 个框，样本很小，波动大）：

| 指标 | 数值 |
|---|---|
| Precision | 0.407 |
| Recall | 0.360 |
| mAP@50 | 0.321 |
| mAP@50-95 | 0.224 |

### 6.3 启用情况与边界说明（2026-10-20 已启用）

- 启用方式：`.env` 里设置 `MODEL_PATH=models/orange_coco_best.pt`、`MODEL_IMGSZ=960`、`MODEL_CONF=0.25`，并在 `MODEL_NOTE` 写明模型来源；页面顶部会显示“已加载模型 …”，不再报“未配置”。
- 效果对比（用户上传的一张橙子堆叠照片，约 30 个果）：OpenCV 演示模式只检出 **1 个**（颜色连通域被粘连成一个整体），该模型在 640 像素下检出 **19 个**，960 像素下检出 **29 个**。耗时：GPU 首次调用约 1.8 秒（含加载/预热），之后单张约 40–50 毫秒。
- 边界：模型只学过“橙黄色、近距离的橙子”，对果园远景、青果、严重遮挡仍然不可靠；类别只有 `orange` 一类，没有成熟度等级。
- 因此页面、估产、报表不会把它说成“陈皮柑专用模型”，论文里也要写明“通用橙类迁移模型”，不能把 0.321 的 mAP 当成陈皮柑精度。
- 如果换上真正的陈皮柑权重（`MODEL_PATH` 指向新文件），把 `MODEL_NOTE` 改成对应说明即可，代码不用动。

### 6.4 要得到可用的陈皮柑模型，实际需要

1. **带标注框的照片**：至少 300～500 张，覆盖晴天/阴天、近景/远景、青果/转色/成熟、遮挡与密集果串；每类（若做成熟度分级）不少于 200 个实例。
2. 训练/验证按 8:2 或按果园划分（同一棵树不要同时出现在训练和验证集，否则指标虚高）。
3. 用 `scripts/train_yolo.py` 训练，把验证集的 P / R / mAP 写进论文，并保留混淆矩阵与 PR 曲线。
4. 成熟度分级必须在标注阶段就作为独立类别，模型不支持的类别不能在系统里宣称。

在拿到上述数据前，任何“已实现陈皮柑识别”的说法都不成立。
## 7. 用公开果园数据集训练（当前线上模型，2026-10-20）

### 7.1 数据来源与许可

- 数据集：**Oranges in the field**（UNIPA Oranges Dataset），5025 张 640×640 果园实拍，含 YOLO 与 COCO 标注。
- 引用：LUCAS, B.; Carella, A.; El Ghazouali, S.; Bulacio, P.; Massenti, R.; Venturini, F.; Michelucci, U.; Lo Bianco, R. (2025), *Oranges in the field*, Mendeley Data, v1, doi:10.17632/93f32zgkxz.1。
- 许可：**CC BY-NC 3.0**（署名—非商业性使用），仅用于本毕业设计的学习与研究，不得商用；论文中引用需注明来源与许可。
- 数据按环境分为 9 个子集（上午/下午/傍晚、晴/阴/雨、室内、夜间），解压后约 810 MB。

### 7.2 下载与整理

Mendeley 单连接被限速到 20–70 KB/s，整包 775 MB。脚本用 16 段 Range 并行 + 断点续传：

```bash
python scripts/download_unipa.py --connections 16   # 约 38 分钟，产出 datasets/unipa/unipa.zip
python scripts/build_unipa_dataset.py              # 解压后整理为 YOLO 目录
```

整理规则：按文件名前缀（果树编号）**分组划分**，训练 2000 张、验证 400 张，避免同一棵树同时出现在训练和验证集导致指标虚高；丢弃空标注。产物在 `datasets/orange_orchard/`，`SOURCE.txt` 记录出处与许可。

### 7.3 训练与指标

```bash
python scripts/train_yolo.py --data datasets/orange_orchard/data.yaml --model models/yolov8n.pt --epochs 30 --imgsz 640 --batch 16 --device 0
```

实际训练：YOLOv8n 从 COCO 预训练权重微调，30 epochs，640×640，batch 16，RTX 4060 约 30 分钟。

| 指标 | 数值 |
|---|---|
| Precision | 0.807 |
| Recall | 0.736 |
| mAP@50 | 0.801 |
| mAP@50-95 | 0.449 |
| 验证集 | 400 张 / 2842 个标注框 |

对比：上一版 COCO orange 模型 mAP50 只有 0.321，且在真实果园图上基本检不出；本版在同一类数据上可用。

### 7.4 接入方式

`.env` 中：

```text
MODEL_PATH=models/orange_orchard_best.pt
MODEL_IMGSZ=640
MODEL_CONF=0.25
MODEL_NOTE=基于 Oranges in the field（UNIPA，5025 张果园实拍，CC BY-NC 3.0）训练的果园橙类模型……
```

页面顶部会显示模型路径、置信度、设备、类别（orange）和上面的说明。

### 7.5 边界（论文必须写明）

1. 训练数据是**意大利橙园**的橙子，不是新会陈皮柑（茶枝柑），品种、果形、叶色都有差异；只能作为“果园柑橘检测”的近似模型。
2. 模型只有 `orange` 一个类别；成熟度由框内颜色比例估算，**不是模型分类**；青果、严重遮挡、过曝仍会漏检。
3. 指标是在同分布验证集上得到的，换到你的果园会下降，需用自己的照片复测。
4. 数据许可为 **CC BY-NC 3.0**，模型仅限非商业用途。
5. 要得到“陈皮柑专用”模型，仍需按第 6.4 节准备带标注的本地照片重新训练。
