# 论文用：检测模型章节（数据、训练、指标）

> 本文档给出可直接改写进毕业论文“系统实现/实验与分析”章节的事实数据：数据集、划分方式、训练配置、评价指标、对比实验、推理性能与局限。所有数值均来自本机实际训练与验证日志（`runs/orange_orchard/`）。

## 1. 任务定义

- 任务：单类别目标检测，类别 `orange`（果园树上的橙黄色柑橘果实）。
- 输入：一张果园实拍图片（JPG/PNG）。
- 输出：每个果实的边界框 $(x_1,y_1,x_2,y_2)$、置信度、类别。
- 下游用途：果实计数、分级统计（按检测框像素占比的相对大小）、样本地块估产。

## 2. 数据集

### 2.1 来源与许可

采用公开数据集 **Oranges in the field**（UNIPA Oranges Dataset）：5025 张 640×640 果园实拍图，覆盖上午/下午/傍晚、晴天/阴天/雨天、室内与夜间等 9 种环境，包含 YOLO 与 COCO 两种标注格式，标注经半自动预标注 + 人工核验。

- 引用：LUCAS, B.; Carella, A.; El Ghazouali, S.; Bulacio, P.; Massenti, R.; Venturini, F.; Michelucci, U.; Lo Bianco, R. (2025). *Oranges in the field*. Mendeley Data, v1. doi:10.17632/93f32zgkxz.1
- 许可：CC BY-NC 3.0（署名—非商业性使用）。本系统仅用于毕业设计研究，不用于商业用途。
- 说明：数据为意大利橙园，**不是新会陈皮柑**；用于验证“果园柑橘检测”技术路线，不能等同于陈皮柑专用模型。

### 2.2 划分与统计

按**果树编号**（文件名前缀，如 `AC006`）分组划分，保证同一棵树不会同时出现在训练集和验证集，避免数据泄漏导致指标虚高；丢弃空标注图片。

| 划分 | 图片数 | 标注框数 | 平均框/图 | 最大框/图 | 环境分布（主要） |
|---|---|---|---|---|---|
| 训练集 | 2000 | 18228 | 9.1 | 96 | 上午晴 1157、下午阴 348、下午晴 257、傍晚晴 83 等 |
| 验证集 | 400 | 2844 | 7.1 | 55 | 上午晴 191、下午阴 102、下午晴 66、傍晚晴 21 等 |

> 写论文时建议同时说明：单类别、类别不均衡程度低（仅一类）、密集小目标比例较高（平均 7–9 个/图）。

## 3. 模型与训练配置

### 3.1 模型选择

选择 **YOLOv8n**（Ultralytics 实现）作为检测器：

- 参数量 **3.14 M**，权重文件 **6.2 MB**，适合本地/边缘部署；
- 从 COCO 预训练权重 `yolov8n.pt` 微调（迁移学习），在小数据集上收敛快；
- 单类别、目标尺度变化大，YOLO 的多尺度特征金字塔适合密集果实场景；
- 对比：YOLOv8s/m 精度可能更高，但参数量与推理成本成倍增加，对本项目“本地实时演示”不划算。

### 3.2 训练超参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 输入尺寸 | 640×640 | 与数据集原始尺寸一致 |
| epochs | 30 | 早停耐心值 10，实际训练满 30 轮 |
| batch size | 16 | 显存允许下的稳定值 |
| 优化器 | auto | 由 Ultralytics 按迭代次数自动选择优化器与学习率 |
| 学习率调度 | 余弦退火（cos_lr=True） | 后期平滑收敛 |
| 混合精度 | AMP 开启 | 加速训练、降低显存 |
| 数据增强 | Mosaic、HSV 色彩抖动、水平翻转、缩放/平移 | Ultralytics 默认增强；最后 10 轮关闭 Mosaic（close_mosaic=10） |
| 随机种子 | 0 | 保证可复现 |
| 设备 | RTX 4060 Laptop（8 GB） | CUDA，fp16 |
| 训练耗时 | 约 27 分钟 | 日志 time=1620.6 s |

### 3.3 训练命令（可复现）

```bash
python scripts/download_unipa.py --connections 16
python scripts/build_unipa_dataset.py --max-train 2000 --max-val 400
python scripts/train_yolo.py --data datasets/orange_orchard/data.yaml --model models/yolov8n.pt --epochs 30 --imgsz 640 --batch 16 --device 0
```

## 4. 评价指标与结果

### 4.1 指标定义

- 精确率 $P = \frac{TP}{TP+FP}$：检出的果实中真正是果实的比例。
- 召回率 $R = \frac{TP}{TP+FN}$：真实果实中被检出的比例。
- $AP$：以召回率为横轴、精确率为纵轴的 PR 曲线下面积；$mAP@50$ 为 IoU 阈值 0.5 时的均值，$mAP@50\text{-}95$ 为 IoU 0.5:0.05:0.95 的平均。
- 本任务只有 1 个类别，因此 $mAP$ 等于该类别的 $AP$。

### 4.2 验证集结果（400 张图 / 2844 个框）

| 指标 | 数值 |
|---|---|
| Precision | **0.807** |
| Recall | **0.736** |
| mAP@50 | **0.801** |
| mAP@50-95 | **0.449** |

### 4.3 对比实验

| 方案 | 训练数据 | mAP@50 | 在真实果园图上的表现 |
|---|---|---|---|
| COCO orange 迁移 | COCO 2017 orange（76 张，236 框） | 0.321 | 基本检不出（0 个框） |
| 本文方案 | UNIPA Oranges（2000 训练 / 400 验证） | **0.801** | 正常检出（验证集与实拍图均可用） |

> 结论：限制模型效果的主要因素是**数据域与标注质量**，不是网络结构；小样本、跨域数据即使能训练，也无法在果园场景使用。

### 4.4 推理性能

| 项目 | 数值 |
|---|---|
| 参数量 | 3.14 M |
| 权重大小 | 6.2 MB |
| 推理设备 | RTX 4060 Laptop（CUDA） |
| 单张耗时（640，预热后） | **约 15 ms**（约 65 FPS 等效） |
| 首次调用 | 约 1.5–1.8 s（含模型加载/预热） |

## 5. 局限与讨论

1. **品种与地域差异**：训练数据为意大利橙园，新会陈皮柑（茶枝柑）在果形、果皮颜色、叶片密度上存在差异，跨域精度会下降，需本地数据复测。
2. **单类别**：模型只输出 `orange`；系统另提供“颜色估算”区分青/转色/成熟，属于后处理规则，不是模型分类，论文中按此表述。
3. **遮挡与逆光**：密集果串、严重遮挡、强逆光会漏检，召回率 0.736 反映了这一点。
4. **指标适用域**：mAP 是在同分布验证集上测得；换果园、换季节后需重新验证。
5. **许可限制**：数据 CC BY-NC 3.0，模型仅限非商业用途。

## 6. 论文可直接改写的段落（示例）

> 本研究采用 YOLOv8n 作为果实检测模型，在公开果园数据集 Oranges in the field（5025 张实拍图，CC BY-NC 3.0）上进行迁移学习。为保证评估客观，按果树编号分组划分训练集 2000 张、验证集 400 张，避免同一棵树同时出现在训练与验证数据中。训练输入尺寸 640×640，batch size 16，迭代 30 轮，采用余弦学习率调度与混合精度训练，在 RTX 4060 上耗时约 27 分钟。验证集包含 2844 个标注框，模型取得 Precision 0.807、Recall 0.736、mAP@50 0.801、mAP@50-95 0.449 的结果，单张推理耗时约 15 ms。与仅使用 COCO orange 子集（76 张）训练的模型（mAP@50 0.321，且在实际果园图片上无法检出）相比，数据规模与标注质量对果园场景的检测性能起决定作用。由于训练数据为国外橙园且仅含单一类别，模型尚未覆盖新会陈皮柑的品种差异与成熟度分级，相关结论仅适用于“果园柑橘果实检测”这一任务。

## 7. 需要补充的本地数据（陈皮柑专用模型）

要把模型从“通用橙类”升级为“新会陈皮柑专用”，需要一批**带标注框**的本地照片，要求如下。

### 7.1 拍什么

- **主体**：新会陈皮柑/茶枝柑**长在树上**的果实，包含单果特写、果串、整树远景；不要拍摘下来堆在桌上/筐里的商品果（那是分拣场景，不是果园检测）。
- **成熟阶段**（若要做分级，必须分开标注）：青果（7–9 月）、转色果（10–11 月）、成熟果（11–12 月）。
- **环境**：晴天顺光、晴天逆光、阴天、傍晚各占一定比例；包含叶片遮挡、果实重叠、远近不同的拍摄距离（0.5–3 m）。
- **负样本**：约 10% 的“无果”画面（空枝、树叶、地面），用于降低误检。

### 7.2 拍多少

| 目标 | 图片数 | 标注框数 | 说明 |
|---|---|---|---|
| 最小可用 | 300 | ≥ 2000 | 单类别“果实”，能跑通训练与验证 |
| 推荐 | 600–800 | ≥ 5000 | 覆盖不同光照/距离，指标更稳 |
| 做成熟度分级 | 每类 ≥ 200 个实例 | 三类合计 ≥ 6000 | 青/转色/熟分别作为类别 |

### 7.3 怎么标

- 工具：LabelImg / X-AnyLabeling / Label Studio 均可，导出 **YOLO 格式**（每行 `类别 cx cy w h`，归一化到 0–1）。
- 规则：框住**可见果实的外接矩形**，被遮挡超过 60% 的果可不标；同一串果逐个标，不合并；漏标比多标危害更大。
- 划分：按**果树/地块**分组划分 8:2，禁止同一棵树的图片跨训练集与验证集。

### 7.4 文件与命名

- 格式 JPG/PNG，长边 ≥ 1280 px，不要加滤镜、水印、拼接图；
- 命名建议 `地块_树号_日期_序号.jpg`（如 `A01_T07_20261120_03.jpg`），便于按树分组；
- 附一份 CSV：文件名、地块、树号、拍摄日期、距离、成熟阶段、备注。

### 7.5 拿到数据后的流程

```text
1) 预标注：用当前模型自动生成框 → 人工在 LabelImg 里纠正（比从零画快 3–5 倍）
2) 训练：python scripts/train_yolo.py --data datasets/chenpigan/data.yaml --epochs 60 --imgsz 640
3) 验证：记录 P/R/mAP50/mAP50-95、混淆矩阵、PR 曲线，与本报告第 4 节对比
4) 上线：把 best.pt 放到 models/，改 .env 的 MODEL_PATH 与 MODEL_NOTE
5) 复测：用未参与训练的本地果园照片做一次盲测，报告漏检/误检案例
```
