# 需求分析

> 依据：毕业设计任务书（题目 10《陈皮柑果园智慧管理系统设计与实现》）与项目要求。本文只描述**已经实现并验证**的功能；未实现或受资源限制的部分在第 6 节明确列出。

## 1. 项目背景与目标

新会陈皮柑种植以家庭果园和合作社为主，巡检记录靠纸笔、估产靠经验，存在三个问题：巡检过程无法追溯、果实数量与等级缺少量化依据、产量预估缺少可复核的计算过程。

本系统面向单机/局域网部署的中小型果园，目标是把“巡检 → 影像 → 识别 → 统计 → 估产 → 报表”做成一条可追溯的数据链：每一步都落库，每个数字都能追到来源图片和计算公式。

## 2. 用户与典型场景

| 角色 | 典型操作 | 系统支持 |
|---|---|---|
| 果园管理员 | 建果园、划地块、定巡检计划、看驾驶舱 | 全部页面 |
| 巡检员 | 按计划上传手机/无人机照片 | 上传、自动识别、补填样本树数 |
| 评委/技术查看 | 查看识别结果、核对报表数字 | 结果页、影像详情、报表下载 |

系统为单机部署，登录用于区分操作者并保护数据，不做多租户。

## 3. 功能需求与实现情况

### P1 基础系统与业务管理

| 编号 | 需求 | 实现情况 |
|---|---|---|
| F1-1 | 驾驶舱展示果园/地块/计划/影像/识别/估产等真实统计与图表，空库显示空状态 | 已实现，数据全部来自数据库 |
| F1-2 | 果园增删改查：编号、名称、区域、面积、品种、种植时间、密度、预计株数、备注 | 已实现，编号唯一；有地块/计划/估产时禁止删除 |
| F1-3 | 地块与果园真实关联：编号、面积、株数、品种、备注、预留经纬度 | 已实现，同一果园内地块编号唯一 |
| F1-4 | 巡检计划：名称、果园/地块、计划与执行日期、负责人、方式、状态；进度按实际记录计算 | 已实现，进度 = 已识别影像数 ÷ 影像总数 |
| F1-5 | 影像：JPG/JPEG/PNG 单张与多张上传、预览、筛选、归档、异常标记、重新识别；原图与结果图分开存 | 已实现，含类型/内容/大小校验与安全文件名 |

### P2 AI 识别

| 编号 | 需求 | 实现情况 |
|---|---|---|
| F2-1 | 模型加载、推理、结果解析、结果图绘制封装为独立服务，模型进程内缓存 | 已实现（app/services/detector.py），按权重文件修改时间自动重载 |
| F2-2 | 模型路径、置信度、IoU、设备从统一配置读取 | 已实现，支持 .env / 环境变量 |
| F2-3 | 保存检测框坐标、类别、置信度、图片关联、状态、结果图 | 已实现（detections / recognition_runs 表） |
| F2-4 | 无陈皮柑专用权重时不得冒充真实识别，须有明确提示与演示模式 | 已实现：默认加载通用橙类模型并在提示条写明“不是陈皮柑专用”；没有权重时自动退回 OpenCV 演示模式，结果标注“演示” |
| F2-5 | 大小分级须说明是相对图像比例；成熟度类别必须与模型类别一致 | 已实现：页面注明“相对图像大小，不代表真实果径”；模型类别取自输出；成熟度另做颜色估算（青/转色/成熟），明确标注非模型分类 |
| F2-6 | 有真实数据时提供训练脚本与真实指标 | 提供 scripts/train_yolo.py、data.yaml 模板与两个建库脚本；先用 COCO orange（76 张）训练（mAP50=0.321，果园图不可用）；随后用公开数据集 Oranges in the field（5025 张果园实拍，CC BY-NC 3.0）训练，验证集 P=0.807 / R=0.736 / mAP50=0.801，已启用并在页面标注“不是陈皮柑专用”，详见 docs/模型接入说明.md 第 7 节 |

### P3 分析与估产

| 编号 | 需求 | 实现情况 |
|---|---|---|
| F3-1 | 结果按果园/地块/批次/时间/类别筛选，可看单图详情，人工复核与模型原始结果区分 | 已实现 |
| F3-2 | 估产支持单株/地块/全园，保存来源、范围、参数、公式、结果与时间 | 已实现（yield_estimates 表含完整参数与公式） |

| F3-4 | 图表来自数据库；无历史数据时不做同比/环比 | 已实现：按“全园”估产按月汇总，缺上月/去年同月时显示“数据不足” |

## 4. 非功能需求

- **可运行性**：Windows 本地 python run.py 即可启动，无需额外服务；SQLite 单文件数据库，重启后数据仍在。
- **性能**：单张 960×720 图片的 OpenCV 演示识别在 0.1 秒量级；YOLO 在 RTX 4060 上为百毫秒量级；影像列表 24 条/页分页。
- **安全**：上传内容用 Pillow 真实解码校验、UUID 文件名、独占模式写入、路径穿越检查、服务端全量表单校验、登录拦截。
- **可维护性**：路由 / 服务 / 模型分层，配置集中在 app/config.py，关键业务规则有自动化测试。
- **可移植性**：仅依赖 Python 与 pip 包，数据库与文件目录均可通过环境变量改路径。

## 5. 业务流程（实际实现）

```text
建果园 → 建地块 → 建巡检计划(批次)
        → 上传影像(可勾选自动识别) → 识别(每张图产生 run + 检测框 + 结果图)
        → 结果筛选/汇总 → 人工复核(可选)
        → 估产(选批次与层级，取模型数或复核数) → 保存参数与公式
        → 驾驶舱/图表 → 报表预览 → 导出 Excel/PDF → 归档下载
        → 业务助手用数据库回答巡检/识别/估产/异常问题
```

## 6. 边界与限制（论文必须如实说明）

1. **没有陈皮柑专用数据集与权重**：检测模型用公开橙园数据训练（UNIPA，mAP50=0.801），品种是国外橙类；成熟度为框内颜色估算，不是模型分类；大小分级是相对像素比例。
2. 没有真实果园图片：库中的图片是脚本生成的合成图，仅用于演示流程。
3. 大小等级是检测框像素占比，不是真实果径；真实果径需要标定物或测距。
4. 没有多期历史产量：同比/环比功能已实现，但当前数据只够显示“数据不足”。
5. 无人机只作为“巡检方式”字段与 GPS 预留字段，没有飞控、航线规划、正射影像。
6. 外部大模型未联调；只有单一管理员账号，没有细分角色权限。
7. 识别为同步执行，大批量图片会阻塞请求；未做后台任务队列。
