## 第 1 章 先懂 7 个词

### 1.1 浏览器和服务器

- 浏览器：你看到的页面，Chrome。
- 服务器：跑 Python 的那台电脑，这里是本机 127.0.0.1:5000。

浏览器不会直接读数据库，它只会发两种东西：

1. 请求：我要哪个网址、带什么数据；
2. 接收响应：HTML 页面，或 JSON 数据。

### 1.2 URL、GET、POST

~~~text
http://127.0.0.1:5000/images/upload
└────── 服务器 ──────┘└── 路径 ──┘
~~~

- GET：打开页面、查数据；
- POST：提交表单、新增/修改。

### 1.3 路由

路由就是一张“网址 → Python 函数”的对照表。

~~~python
@bp.route("/upload", methods=["GET", "POST"])
def upload():
    ...
~~~

意思是：访问 /images/upload 时，执行 upload() 这个函数。

### 1.4 模板

模板是“带占位符的 HTML”。

~~~html
<h1>{{ orchard.name }}</h1>
{% for p in plots %}
  <tr><td>{{ p.code }}</td></tr>
{% endfor %}
~~~

后端把数据交给模板，模板把 {{ }} 替换成真实值，生成最终 HTML。

### 1.5 数据库和表

数据库文件是 instance/orchard.db，里面是 10 张表。

一张表就像一张 Excel：

- 一行 = 一条记录（一个果园、一张照片）；
- 一列 = 一个字段（名称、面积、状态）；
- id = 行号，用来被别的表引用。

### 1.6 ORM

ORM 让你用 Python 类操作表，不用手写 SQL。

~~~python
class Orchard(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(100))
~~~

查询：

~~~python
Orchard.query.filter_by(code="XH-01").first()
~~~

翻译成 SQL 就是 SELECT ... FROM orchards WHERE code='XH-01'。

### 1.7 为什么点一下按钮，就能连到后端

因为浏览器发了一个 HTTP 请求：

~~~text
POST /images/upload
Cookie: session=...
Content-Type: multipart/form-data
（照片二进制）
~~~

Flask 收到后：

1. 看路径 /images/upload；
2. 查路由表，找到 images.upload；
3. 把表单、文件、Cookie 放进 request；
4. 执行函数；
5. 函数返回 HTML 或重定向；
6. 浏览器显示结果。

**前后端不是“互相调用函数”，而是通过 HTTP 请求和响应通信。**

### 1.8 为什么后端能改数据库

因为 Python 进程打开 orchard.db 这个文件时，是“可读写”模式：

~~~text
Flask 进程
  → SQLAlchemy 生成 SQL
  → SQLite 引擎打开 orchard.db
  → 修改数据页
  → 写 WAL 日志
  → commit 后其他程序能读到
~~~

数据库不是“只读文件”，它和 Word 文档一样，可以被打开、修改、保存。

## 第 3 章 启动原理：python run.py 之后

### 3.1 run.py

~~~python
from app import create_app
app = create_app()
if __name__ == "__main__":
    app.run(host="127.0.0.1", port=5000)
~~~

- 第 1 行：导入应用工厂；
- 第 2 行：把应用建出来；
- 第 3 行：只有直接运行才启动；
- 第 4 行：监听 5000 端口。

### 3.2 create_app() 按顺序做的 7 件事

~~~python
load_dotenv(BASE_DIR / ".env")      # 1. 先读 .env
from .config import Config          # 2. 再导入配置
app = Flask(__name__)               # 3. 创建应用
app.config.from_object(Config)      # 4. 加载配置
db.init_app(app)                    # 5. 绑定数据库
register_blueprints(app)            # 6. 注册 13 组路由
db.create_all(); _ensure_schema()   # 7. 建表、补列
~~~

为什么 .env 必须在 config 之前？

因为 config.py 里的值是在“导入那一刻”读环境变量的。如果先导入 config，.env 还没读，配置就永远是默认值。

### 3.3 登录拦截

~~~python
@app.before_request
def _require_login():
    if not app.config.get("AUTH_ENABLED", True):
        return None
    if request.endpoint in ("static", "auth.login", "main.landing"):
        return None
    if getattr(g, "user", None):
        return None
    if request.path.startswith(("/api/", "/assistant/ask")):
        return jsonify(error="未登录或会话已过期"), 401
    return redirect(url_for("auth.login", next=request.full_path))
~~~

每个请求进来前都会跑：

- 静态文件、登录页、首页放行；
- 接口没登录返回 401；
- 页面没登录跳登录页。

### 3.4 旧库自动补列

~~~python
wanted = {
    "detections": {"maturity": "VARCHAR(10)"},
    "recognition_runs": {"maturity_counts": "JSON"},
    "images": {"source": "VARCHAR(20)"},
}
if name not in existing:
    conn.execute(text(f'ALTER TABLE "{table}" ADD COLUMN {name} {ddl}'))
~~~

create_all() 只会建新表，不会给旧表加列，所以自己写了一个轻量迁移。

## 第 4 章 数据库：10 张表和关系

### 4.1 表清单

| 表 | 一行代表 | 关键字段 |
|---|---|---|
| orchards | 一个果园 | code 唯一、name、area_mu、variety、density、expected_trees |
| plots | 一个地块 | orchard_id、code、area_mu、tree_count |
| inspection_plans | 一次巡检计划 | orchard_id、plot_id、planned_date、status |
| images | 一张照片 | plan_id、stored_path、width/height、sample_trees、status、source |
| recognition_runs | 一次识别 | image_id、status、total_count、class_counts、size_counts、maturity_counts、reviewed_count |
| detections | 一个检测框 | run_id、class_name、confidence、x1..y2、area_ratio、size_grade、maturity |
| yield_estimates | 一条估产 | level、orchard_id、plot_id、样本/目标/系数/单果重、est_yield_kg、formula |
| harvest_records | 一条实际采收 | orchard_id、year、actual_yield_kg、avg_price |
| reports | 一次报表导出 | report_type、fmt、file_path、params |
| users | 一个用户 | username、password_hash、role、is_active |

### 4.2 关系

~~~text
Orchard 1─n Plot 1─n InspectionPlan 1─n ImageRecord 1─n RecognitionRun 1─n Detection
   │                    │
   └── YieldEstimate ───┘        HarvestRecord（按果园/地块/年）
ReportRecord（导出文件）   User（登录）
~~~

### 4.3 为什么检测框要单独一张表

如果只存“这张图 30 个果”，后面就做不到：

- 人工复核每个框；
- 按大小、成熟度统计；
- 在结果图上画框；
- 追溯某个框的置信度。

所以一个果子一行，存坐标、置信度、面积占比、大小、成熟度。

### 4.4 为什么人工复核不覆盖模型结果

recognition_runs 里有两套数：

- total_count：模型原始数；
- reviewed_count：人工复核数。

页面同时显示，报表可以选择用哪套。这样模型结果永远可追溯，不会被人工改乱。

### 4.5 为什么用 JSON 字段

class_counts、size_counts、maturity_counts 是“类别 → 数量”的字典。

如果拆成多张表，查询会变复杂；存 JSON 一行就能取，适合这种统计快照。

### 4.6 删除保护

- 果园有地块/计划/估产 → 不能删；
- 地块有计划/估产 → 不能删；
- 计划有影像/估产 → 不能删（可改“已取消”）；
- 已归档影像不能删；
- 删影像级联删识别记录和文件。

代码在 routes 的 delete 函数里先查关联，再决定能不能删。

### 4.7 一次数据库写入

~~~python
orchard = Orchard(code="XH-01", name="示范园")
db.session.add(orchard)
db.session.commit()
~~~

- add：把对象放进 session（待保存队列）；
- commit：生成 INSERT，写进 SQLite；
- 失败：rollback，撤销这次事务。

### 4.8 WAL 是什么

~~~text
orchard.db      主文件
orchard.db-wal  刚写入的变更
orchard.db-shm  共享内存索引
~~~

写操作先记 WAL，commit 后其他程序能读到；之后 checkpoint 合并回主文件。

所以刚写完时，主 .db 可能没变，但数据已经“算数”了。

## 第 5 章 后端接口：13 个路由模块

### 5.1 接口是什么

每个 @bp.route(...) 就是一个接口：

~~~python
@bp.route("/new", methods=["GET", "POST"])
def create():
    if request.method == "POST":
        ...
    return render_template("orchards/form.html")
~~~

- 路径：/orchards/new
- 方法：GET 显示表单，POST 保存
- 返回：HTML 或 redirect

接口分两类：

1. 页面接口：返回 render_template / redirect；
2. JSON 接口：返回 jsonify，给 fetch 用。

## 第 6 章 服务层：真正干活的 8 个文件

### 6.1 storage.py：上传五道校验

~~~python
original = (file_storage.filename or "").replace("\\", "/").split("/")[-1].strip()
ext = _ext(original)
if ext not in ALLOWED_IMAGE_EXTENSIONS:
    raise UploadError("仅支持 JPG/JPEG/PNG")
data = file_storage.read()
if not data or len(data) > MAX_IMAGE_SIZE:
    raise UploadError("文件为空或过大")
with Image.open(BytesIO(data)) as img:
    fmt = img.format
    img.verify()
if fmt not in PIL_FORMATS or ext not in PIL_FORMATS[fmt]:
    raise UploadError("内容与扩展名不符")
rel = f"originals/{YYYYMM}/{uuid4().hex}.jpg"
with open(full, "xb") as fh:
    fh.write(data)
~~~

逐句：

- 文件名只留最后一段，防止 ../../；
- 扩展名白名单；
- 文件不能为空、不能超大小；
- Pillow 真正解码，防止改后缀的假图；
- 格式必须和扩展名一致；
- UUID 新文件名，xb 模式独占写入，不覆盖。

同时读 EXIF 拍摄时间和 GPS。

### 6.2 detector.py：模型怎么跑

~~~python
def resolve_mode(mode):
    if mode == "auto":
        return "yolo" if ultralytics_available() and Path(MODEL_PATH).is_file() else "opencv_demo"
    return mode
~~~

- auto：有模型用 yolo，没有用演示；
- 演示模式会在页面和报表标注“演示”。

~~~python
def detect_array(img, mode):
    dets, model_name, device = _detect_yolo(img)
    for d in dets:
        d["area_ratio"] = (x2-x1)*(y2-y1)/(w*h)
        d["size_grade"] = size_grade(d["area_ratio"])
        d["maturity"] = maturity_grade(img, d)
    return {...}
~~~

后处理是“你的设计”：

- 面积占比：框面积 ÷ 整图面积；
- 大小：小于 0.002 小，大于 0.008 大，中间中；
- 成熟度：框内橙黄像素 ÷（橙黄+绿），≥0.55 成熟，≥0.2 转色，否则青。

模型只给框，后面的等级是你定的规则。

### 6.3 recognition.py：一次识别的事务

~~~python
run = RecognitionRun(image_id=image.id, status="失败")
try:
    run.mode = detector.resolve_mode(mode)
    out = detector.detect(resolve(image.stored_path), run.mode)
    run.status = "成功"
    run.total_count = len(dets)
    run.class_counts = dict(Counter(...))
    for d in dets:
        run.detections.append(Detection(**d))
except Exception as e:
    run.error_message = str(e)[:1000]
db.session.add(run)
db.session.commit()
~~~

设计点：

- 先建失败记录，失败也留痕；
- 成功才写检测框；
- 异常不抛出，批量识别不中断；
- 一次 commit，run 和 detections 一起成功/失败。

### 6.4 stats.py：统计口径

~~~python
def latest_run_ids():
    return db.session.query(func.max(RecognitionRun.id)) \
        .filter(RecognitionRun.status == "成功") \
        .group_by(RecognitionRun.image_id)
~~~

SQL 意思：每张图取最新一次成功的 run id。

summarize() 把多行 run 汇总成：

- 图片数、模型总数、复核后总数；
- 类别、大小、成熟度计数。

coverage_data()：每个地块计划数、已开展、影像数、识别率、覆盖率。

yield_trend()：按月汇总全园估产，算环比/同比，缺数据返回 None。

### 6.5 yield_service.py：估产公式

~~~python
if not sample_tree_count or sample_tree_count <= 0:
    raise YieldError("样本树数必须大于 0")
avg = sample_fruit_count / sample_tree_count
est_count = avg * target_tree_count * correction_factor
est_yield = est_count * avg_fruit_weight_g / 1000
~~~

目标树数：

- 单株 = 1；
- 地块 = plot.tree_count；
- 全园 = orchard.expected_trees，为空取地块合计。

collect_samples() 只统计填了 sample_trees 的图片，避免除零。

### 6.6 reports.py：内容和格式分离

build() 只产出：

~~~python
{"title": ..., "meta": [...], "sections": [
  {"title": "一、...", "header": [...], "rows": [[...]], "note": "..."}
], "warnings": [...]}
~~~

to_excel() 写单元格；to_pdf() 排版。

设计点：加 Word 导出时不用重写业务数据。

### 6.7 security.py：密码和会话

- hash_password：PBKDF2-SHA256；
- verify_password：比对哈希；
- login_user：session.clear + session["uid"]；
- load_current_user：每个请求按 uid 查库。

数据库不存明文密码。

### 6.8 llm.py：本地大模型

~~~python
facts = answer_from_db(question) or context_facts()
answer = llm.ask(question, facts)
~~~

设计点：

- 先查库得到事实；
- 提示词要求只依据事实；
- 模型超时/没装 → 只用规则答案；
- 页面展示 facts，用户可核对。

## 第 9 章 模型训练：从数据到权重

### 9.1 数据从哪来

- 公开数据集 Oranges in the field（UNIPA）；
- 5025 张果园实拍；
- 许可 CC BY-NC 3.0（非商业）；
- 不是新会陈皮柑专用数据。

### 9.2 处理流程

~~~bash
python scripts/download_unipa.py --connections 16
python scripts/build_unipa_dataset.py --max-train 2000 --max-val 400
python scripts/train_yolo.py --data datasets/orange_orchard/data.yaml \
  --model models/yolov8n.pt --epochs 30 --imgsz 640 --batch 16 --device 0
~~~

- 下载：HTTP Range 分段、断点续传；
- 建库：按果树编号分组，避免同一棵树同时进训练和验证；
- 训练：YOLOv8n 从 COCO 预训练权重微调。

### 9.3 指标怎么读

- P（Precision）：检出的里面有多少是对的；
- R（Recall）：真实的里面检出了多少；
- mAP@50：IoU=0.5 时的平均精度；
- 当前：P 0.807 / R 0.736 / mAP50 0.801 / mAP50-95 0.449。

### 9.4 训练是谁做的

- 网络结构、损失、NMS、训练循环：Ultralytics/PyTorch；
- 数据整理、划分、参数、评估、接入、后处理：你做的。

### 9.5 推理怎么接进系统

~~~text
图片 → read_image → YOLO 预测 → 框
  → 面积占比/大小/成熟度
  → draw_result 画框
  → run + detections 入库
~~~

换模型只改 .env 的 MODEL_PATH 和 MODEL_NOTE，代码不用动。

### 9.6 边界

- 不是陈皮柑专用；
- 成熟度是颜色估算，不是模型分类；
- 大小是相对像素，不是真实果径；
- 远景、青果、遮挡会漏检。

## 第 12 章 答辩/面试口径

### 12.1 你怎么设计的

> 先按业务对象设计 10 张表，再按“路由收请求、服务放规则、模型连数据库”分三层；关键规则是最新一次成功识别、上传五道校验、估产参数全入库、报表从库重新组装。

### 12.2 为什么用 Flask / SQLite / YOLOv8n

- Flask：轻量、可控、适合单机；
- SQLite：零安装、单文件、事务够用；
- YOLOv8n：小、快、4060 能训。

### 12.3 几千行是你写的吗

> 不是每行都手敲。框架和库是开源的；我写的是业务层和设计。项目里任何一段业务代码，我都能解释和修改。

### 12.4 常见追问

| 问题 | 一句话答 |
|---|---|
| 为什么检测框单独表 | 要存坐标、置信度、大小、成熟度，支持复核和画框 |
| 为什么只取最新成功 run | 重识别不重复计数 |
| 上传怎么防攻击 | 文件名去路径、白名单、真解码、UUID、独占写入 |
| 估产为什么不会重复乘 | 样本树数是这些照片覆盖的树，不是整地块 |
| mAP 0.801 怎么来的 | 5025 张、2000/400、30 轮、验证集指标 |
| 成熟度为什么是颜色 | 模型没有成熟度类别，颜色估算是后处理 |
| 实时框怎么对齐 | contain 显示区域 + 偏移 + 缩放 |
| 报表怎么保证一致 | 每次都查库，不写死 |
| 最大困难 | 任选：.env 顺序、SQLite 补列、框对齐、无专用数据 |

### 12.5 不要说的话

- “全是我一行行敲的”；
- “YOLO 网络是我写的”；
- “我不知道，是自动生成的”。
