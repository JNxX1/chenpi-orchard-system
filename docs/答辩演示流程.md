# 答辩演示流程

## 1. 演示前准备（提前 10 分钟）

1. 激活环境并启动服务：

```text
conda activate Deep
cd D:\毕业设计
python run.py
```

2. 浏览器打开 http://127.0.0.1:5000 ，用 admin 登录（初始密码见 README，首次登录请先改密码，答辩机可提前改好）。
3. 确认驾驶舱有数据：果园 1 个、地块 3 个、计划 3 个、影像 6 张、识别目标约 190 个、1 条全园估产。
4. 准备好 2~3 张真实果园照片放在桌面（**不要**用系统里的合成图当真实照片讲）。
5. 提前打开标签页：驾驶舱、巡检计划、影像详情、估产、报表。

## 2. 演示脚本（约 8 分钟）

| 时间 | 操作 | 讲解要点 |
|---|---|---|
| 0:00 | 打开驾驶舱 | 一句话说明选题：把巡检、识别、估产、报表串成可追溯的数据链；指出数字都来自数据库，不是写死的 |
| 0:40 | 果园 → 地块 → 巡检计划 | 强调关联关系与删除保护；计划进度按已识别影像实时计算 |
| 1:40 | 上传 1~2 张真实照片，勾选“自动识别” | 说明校验（类型/大小/伪造内容）、文件改名存储、原图与结果图分开存 |
| 3:00 | 影像详情 | 讲识别方式标注：有陈皮柑权重时显示 YOLO；当前没有权重，退回 OpenCV 演示模式并明确标注“非深度学习” |
| 4:00 | 人工复核 | 说明模型原始结果与复核结果分字段保存，统计时可选来源 |
| 4:20 | 实时识别页 | 选果园后开摄像头/选样片，展示逐帧框选、数量、耗时与**实时产值估算**；说明不落库、仅现场参考 |
| 4:40 | 新建估产（地块/全园） | 念公式：平均可见果数 × 目标树数 × 校正系数 × 单果重；说明参数全部落库、可追溯 |
| 5:40 | 产量估算 + 采收记录 | 展示同比/环比“数据不足”；切到采收记录，说明实际产量如何与估产对比、偏差怎么算 |
| 6:20 | 报表中心 → 导出 PDF | 打开 PDF 展示中文与数值一致性；说明演示数据在报表中有标记 |
| 7:00 | 业务助手 | 问“系统里有多少个果园、多少张影像”，展示 AI 回答并展开“数据库依据”，说明数字来自数据库、模型只负责表达 |
| 7:40 | 收尾 | 说明已完成闭环、已知限制（无专用模型/无真实数据/无人机未接入）与下一步工作 |

## 3. 常见提问与回答

**问：为什么识别结果是“演示模式”？**
答：项目没有拿到陈皮柑数据集和训练好的权重，用通用 COCO 权重冒充专用模型是不诚实的。所以保留完整 YOLO 推理接口，缺权重时退回 OpenCV 颜色阈值演示，并在页面、估产、报表三处标注。拿到数据后复制为 models/chenpigan_best.pt 即可切换，无需改代码。

**问：大小分级准不准？**
答：当前等级来自检测框面积占整图的比例，只是相对大小，受拍摄距离影响，不代表真实果径。真实果径需要标定物或测距，系统里写明了这个限制。

**问：估产公式为什么这样设计？**
答：样本平均可见果数 = 样本检测果数 ÷ 样本树数；预计总果数 = 平均可见果数 × 目标树数 × 校正系数；预计产量 = 总果数 × 单果重 ÷ 1000。样本按树统计，避免把整地块结果再次乘树数造成重复计算。

**问：数据存在哪里？重启会丢吗？**
答：SQLite 单文件 instance/orchard.db，图片在 storage 下按年月分目录。演示中会现场重启服务，数据仍在。

**问：密码怎么存的？**
答：PBKDF2-SHA256 哈希，库里没有明文；会话只存用户 id，账号禁用后立即失效。

## 5. 兜底方案

- 服务起不来：先看控制台报错；端口占用时设置 PORT=5001 再启动。
- 忘记密码：在项目目录执行 python scripts/reset_admin.py，按提示输入新密码即可（不改动业务数据）。
- 没有网络：系统全部本地运行，Chart.js 也是本地文件，不受影响。
- 演示图片过大：单张限制 15 MB，超限会有明确提示。
