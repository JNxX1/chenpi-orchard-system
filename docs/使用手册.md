# 使用手册

面向使用者（果园管理员 / 答辩演示）的操作说明。开发与接口细节见 [系统设计](系统设计.md)。

## 1. 启动与登录

```bat
conda activate Deep
cd /d D:\毕业设计
python run.py
```

浏览器打开 http://127.0.0.1:5000 ，先看到对外首页（未登录也能看），点「进入系统 / 登录系统」进入控制台。

- 账号：admin，初始密码：admin123（首次登录会强制跳转修改密码）
- 忘记密码：在项目目录执行 `python scripts/reset_admin.py`
- 端口被占用：先 `set PORT=5001` 再启动，然后访问 http://127.0.0.1:5001
- 关闭服务：在运行窗口按 Ctrl+C

## 2. 页面地图

| 菜单 | 作用 | 常见操作 |
|---|---|---|
| 首页驾驶舱 | 总览 | 看果园/地块/计划/影像/识别/估产数量、图表、最近巡检 |
| 果园管理 | 建档 | 新增果园、编辑、删除（有地块/计划/估产时不允许删） |
| 地块管理 | 划地块 | 关联果园，填面积、株数、品种，可填经纬度 |
| 巡检计划 | 定批次 | 一个计划就是一次影像采集批次，填日期、负责人、方式；可改状态 |
| 影像管理 | 传图 | 多选上传、预览、筛选、归档、标记异常、重新识别、批量识别 |
| 识别结果 | 看数 | 按果园/地块/批次/时间/类别筛选，查看明细、成熟度分布，做人工复核 |
| 采收记录 | 记实际产量 | 按果园/地块/年份登记实际采收，自动对比估产偏差 |
| 产量估算 | 估产 | 单株/地块/全园三级估产，保存参数与公式，查看同比/环比 |
| 报表中心 | 出报表 | 巡检报告、分级统计、估产报告，导出 Excel/PDF 并归档 |
| 实时识别 | 演示 | 开摄像头或选图片实时框选；选果园后按当前帧估算全园果数、产量与产值，不写库 |
| 业务助手 | 问答 | 查数据库 + 本地 AI（qwen3:8b）组织语言；支持柑橘病虫害知识问答；可展开依据核对 |
| 数据浏览 | 看库 | 只读查看 10 张表的结构与记录，支持搜索、翻页、导出 CSV |

右上角显示当前账号，侧栏底部可改密码、退出。

## 3. 一次完整的业务流程

1. **建果园**：果园管理 → 新增果园。编号唯一（如 XH-001），预计株数用于全园估产。
2. **建地块**：地块管理 → 新增地块，选择所属果园。株数用于地块级估产。
3. **建巡检计划**：巡检计划 → 新建计划，选果园/地块、计划日期。状态先设为“待执行”。
4. **上传影像**：影像管理 → 上传影像，选批次，多选 JPG/PNG，按需填“每张图覆盖的样本树数”，勾选“上传后立即自动识别”。
5. **看识别结果**：影像详情里对比原图与结果图，可点图片放大；下方“人工复核果数”填入你实际数的果数（不会覆盖模型结果）。成熟度显示为“颜色估算”（青/转色/成熟），不是模型分类。
6. **估产**：产量估算 → 新建估产，选批次与层级（单株/地块/全园），填校正系数、平均单果重（克）。系统按公式算出预计果数与产量。
7. **出报表**：报表中心 → 选类型、果园/批次、日期范围 → 生成预览 → 导出 Excel 或 PDF，导出记录自动归档可重复下载。
8. **采收后登记实际产量**：采收记录 → 新增记录，按果园/地块/年份填实际 kg；产量估算页和估产报告会出现“估产 vs 实际采收”的偏差。

> 当前没有陈皮柑专用模型，检测使用公开橙园训练的模型；成熟度是颜色估算，不是模型分类。演示模式与演示数据在页面、报表中都会标注。

## 4. 数据存在哪里

| 内容 | 位置 | 说明 |
|---|---|---|
| 数据库 | `D:\毕业设计\instance\orchard.db` | SQLite 单文件，所有业务数据都在里面 |
| 上传原图 | `storage/originals/年月/` | 文件名由系统生成（UUID），不用你原来的文件名 |
| 识别结果图 | `storage/results/年月/` | 画了检测框的图 |
| 导出的报表 | `storage/reports/` | Excel / PDF 文件 |
| 训练数据与权重 | `datasets/`、`models/`、`runs/` | 数据集、模型权重、训练日志 |

数据库里有 10 张表：`orchards` 果园、`plots` 地块、`inspection_plans` 巡检计划、`images` 影像、`recognition_runs` 识别记录、`detections` 检测框、`yield_estimates` 估产、`harvest_records` 实际采收、`reports` 报表归档、`users` 用户。

## 5. 怎么查看数据库

### 方式一：系统内置“数据浏览”页面（最直观）

登录后点左侧 **数据浏览**（http://127.0.0.1:5000/database/ ）：

- 顶部是数据总览（表数、总记录数、文件大小）和「各表记录数」彩色柱状图；左侧表名带类别色点与占比条；
- 左边列出全部 10 张表，每张表显示行数；
- 右边是当前表的记录，可翻页、按关键字搜索（会搜索该表所有文本列）；
- 展开“字段说明”能看到每列的英文名、中文含义、类型和是否主键；
- 「导出 CSV」把当前表导出成 Excel 能直接打开的 CSV（带 BOM，不乱码）。

此页只读，不能修改数据；要改数据请回到对应功能页面。

### 方式二：项目自带脚本（只读）

```bat
python scripts/db_view.py                          # 所有表和行数
python scripts/db_view.py --table orchards         # 看果园表内容
python scripts/db_view.py --table images --limit 5 # 只看前 5 行
python scripts/db_view.py --sql "select name,area_mu from orchards"
```

脚本以只读方式打开，不会改数据；中文正常显示。

### 方式三：数据库软件 DB Browser（已内置便携版）

项目里已经放好便携版（免安装）：**双击项目根目录的「打开数据库.bat」**，会自动用 DB Browser 打开 instance/orchard.db，在“浏览数据 / Browse Data”页选表即可查看、筛选、排序。

- 可执行文件：tools\DBBrowser\DB Browser for SQLite.exe（20 MB，随项目附带，不提交到 Git）
- 也可以自己装官方版：https://sqlitebrowser.org/
- 想看表关系：切到“数据库结构 / Database Structure”页，或点“工具 → 数据库结构图”
- 注意：在这里改数据不会触发业务校验，容易破坏关联；核对数据可以，修改请回系统页面。

### 方式四：命令行

```bat
python -c "import sqlite3;c=sqlite3.connect(r'instance/orchard.db');print(c.execute('select count(*) from images').fetchone())"
```

## 6. 备份、迁移与重置

- **备份**：先关闭服务，复制整个 `instance` 和 `storage` 目录即可（数据库 + 图片 + 报表）。
- **迁移到另一台电脑**：复制项目目录 + `instance` + `storage`，装好依赖后 `python run.py`。
- **重置演示数据**：关闭服务，删除 `instance/orchard.db` 和 `storage` 下对应文件，再运行 `python run.py`（会重建空库和初始管理员）。**删除前先备份**。
- **只重写演示基础数据**（不删数据）：`python scripts/seed_demo.py`；带合成演示图片：`python scripts/seed_demo.py --with-images`。

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 一直跳登录页 | 会话过期（默认 8 小时），重新登录；连续错 5 次会锁定 |
| 页面提示“已加载模型 … 不是陈皮柑专用模型” | 当前用的是公开果园数据集训练的橙类模型（mAP50=0.801），属正常提示；要换专用权重见 [模型接入说明](模型接入说明.md) |
| 识别结果很少或为 0 | 远景/青果/遮挡严重时通用模型容易漏检，可换近距离照片，或改用“OpenCV 演示模式”对比 |
| 上传提示“不是有效的图片文件” | 改了扩展名的假图片，或文件损坏 |
| 上传提示超过 15 MB | 单张限制，可在 `.env` 改 `MAX_IMAGE_SIZE_MB` |
| 估产提示“样本树数必须大于 0” | 影像详情或上传时补填“样本树数” |
| PDF 中文乱码 | 缺少 `C:\Windows\Fonts\simhei.ttf` 或 `simsun.ttc` |
| 首页数字都是 0 | 还没有数据，或数据库被换成了空库 |
